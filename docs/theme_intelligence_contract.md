# Theme Intelligence Contract

Phase 10.10 adds a curated seed evidence layer and response-shape QA for the Theme Intelligence backend. The seed layer is infrastructure data only: it does not assign final AI scores, discovery scores, or portfolio weights.

## Seed Themes

The curated seed package covers:

- Glass Substrate
- HBM
- CoWoS
- AI Infrastructure
- Advanced Packaging
- Power Grid
- CPO Photonics
- Robotics
- Edge AI
- Data Center Cooling

Each seed includes `theme_id`, canonical English name, Traditional Chinese label, aliases, supply-chain roles, catalysts, bottlenecks, beneficiaries, controllers, resolution enablers, lifecycle hints, and risk notes. Persisted seed evidence is marked with `source = "seed:curated"` for catalyst rows and source metadata inside bottleneck evidence.

## Validator Rules

The seed validator fails on:

- missing `theme_id`, name, Chinese label, aliases, catalysts, bottlenecks, beneficiaries, lifecycle hint, or risk notes
- duplicate aliases or duplicate tickers within a supply-chain role
- invalid lifecycle stage, catalyst type, bottleneck type, timeline status, or beneficiary type
- missing ticker, company name, or role for any beneficiary/controller/enabler row
- controller/direct beneficiary overlap without explicit dual-role rationale
- mojibake markers or empty display fields
- forbidden score/weight fields such as `final_ai_score`, `discovery_score`, `portfolio_weight`, or `weight`

## API Contract

The following Phase 10 endpoints must return stable JSON objects and must not require live providers in contract tests:

- `GET /api/theme/intelligence`
- `GET /api/theme/intelligence/top`
- `GET /api/theme/discovery`
- `GET /api/theme/lifecycle`
- `GET /api/theme/lifecycle/{theme_id}`
- `GET /api/theme/catalysts`
- `GET /api/theme/catalysts/{theme_id}`
- `GET /api/theme/bottlenecks`
- `GET /api/theme/bottlenecks/{theme_id}`
- `GET /api/theme/beneficiaries`
- `GET /api/theme/beneficiaries/{theme_id}`
- `GET /api/theme/scores`
- `GET /api/theme/scores/{theme_id}`
- `GET /api/theme/portfolio`
- `GET /api/theme/portfolio/{portfolio_type}`
- `GET /api/theme/intelligence/{theme_id}`

Theme detail payloads must expose the same top-level sections:

```json
{
  "theme_id": "glass_substrate",
  "name": "Glass Substrate",
  "score": {},
  "discovery": {},
  "lifecycle": {},
  "catalysts": {
    "top_catalysts": []
  },
  "bottlenecks": {
    "primary_bottleneck": null
  },
  "beneficiaries": {
    "top_beneficiaries": []
  },
  "portfolio_context": {
    "portfolios": []
  }
}
```

Missing themes must return honest empty sections rather than fabricated fallbacks.

## Frontend Contract

Frontend contract tests cover API path normalization, detail fetch behavior, aggregate-section expectations, and forbidden static fallback patterns. They are source-contract tests only and do not modify the Theme Discovery page, Dashboard, Rotation page, Supply Chain page, Stock Research page, or UI layout.

## Scoring Boundary

Seed data may improve input coverage for discovery, lifecycle, catalyst, bottleneck, beneficiary, score, and portfolio engines. Final AI scores and portfolio allocations remain generated by existing engine formulas and persisted repository outputs.
